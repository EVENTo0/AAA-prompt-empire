# Evergreen Technology Intelligence

1. Start from the project outcome, current stack, target platforms, risk level, lifecycle, and existing proven dependencies.
2. For fast-moving choices, verify current primary documentation before recommending adoption, upgrade, migration, or removal.
3. Capture stable/recommended channels, support windows, deprecations, breaking changes, migration notes, security advisories, pricing or quota changes when material, and platform/store policy constraints.
4. Distinguish generally available/stable capabilities from preview, beta, experimental, deprecated, or region-limited capabilities.
5. Compare the current proven option against alternatives using measurable project requirements; novelty alone is not a reason to migrate.
6. Prefer reversible pilots for uncertain changes. Define rollback, compatibility, and evidence needed before promotion.
7. Record decision freshness: source date, version/channel, assumptions, and what event should trigger re-checking.
8. Never convert external marketing claims into verified project capability without project-level evidence.

Deliver a concise technology brief with current-state evidence, relevant change, project impact, recommendation, migration/rollback notes, and revalidation trigger.
