# Web Delivery

1. Identify rendering/delivery needs: static, SSR, SPA, PWA, edge, CMS, or hybrid; retain an existing suitable approach.
2. Define responsive states from small phones through large screens; design touch and keyboard behavior together.
3. Implement semantic structure, accessible forms/navigation, loading/empty/error states, localization/RTL where required, and resilient network behavior.
4. Protect client/server trust boundaries; never expose privileged secrets or rely on client-only authorization.
5. Measure meaningful performance: startup/loading, interaction latency, asset weight, image/media behavior, and runtime regressions.
6. Verify critical flows in representative major browsers and at least one physical phone when mobile use matters.
7. Produce a secure branch/PR preview URL where the hosting workflow supports it.
8. Check metadata/SEO/caching only when relevant to the product, not by ritual.

Deliver browser/device evidence, accessibility/performance findings, known limitations, and deploy/rollback path.
