# Performance, Reliability & Accessibility

1. Define measurable budgets tied to user experience before optimizing.
2. Profile representative workloads/devices; identify bottlenecks from evidence, not intuition.
3. Cover startup/load, interaction latency, rendering/frame time, memory, CPU/GPU, asset/network weight, battery/thermal and backend latency/concurrency as applicable.
4. Test degradation: slow/lost network, retries, timeouts, partial dependency failure, low-memory/lifecycle events and recovery.
5. Verify semantic structure, keyboard/focus/touch behavior, screen-reader labels, text scaling, contrast, motion, error messaging and platform accessibility expectations as applicable.
6. Preserve correctness while optimizing; benchmark before/after and detect regressions in CI where worthwhile.
7. Avoid premature micro-optimization and accessibility overlays that hide structural issues.

Deliver measurements, tested devices/environments, bottlenecks, changes, before/after evidence, accessibility findings and remaining risks.
