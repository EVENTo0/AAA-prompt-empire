# Mobile Delivery

1. Confirm target OS versions/devices, store/distribution needs, native integrations, offline/realtime behavior, background work, notifications, deep links, media, accessibility, and privacy.
2. Select the cross-platform stack only after comparing native escape hatches, build/signing path, library health, performance, and operator workflow.
3. Design phone-first UI for safe areas, text scaling, keyboard, touch targets, orientation, lifecycle, permissions, interrupted networks, and restore/retry behavior.
4. Use a development client/internal distribution or cloud build when native modules prevent a lightweight preview client.
5. Keep platform-specific code isolated behind clear boundaries.
6. Verify on at least one representative physical device before claiming mobile readiness; add emulator/device-farm coverage based on risk.
7. Profile startup, memory, CPU/GPU, battery and data use when material.
8. Treat signing keys, certificates, provisioning data, service credentials, and store secrets as protected infrastructure, never source files.

Return the fastest phone-install/preview path, tested device matrix, build evidence, and store/release blockers.
