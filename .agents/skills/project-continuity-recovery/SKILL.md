# Project Continuity & Recovery

1. Locate the authoritative project repository, active branches/PRs, product brief, architecture/ADR records, deployment state, project registry entry, and latest verification evidence.
2. Reconstruct the last verified outcome, incomplete acceptance criteria, blockers, dependencies, and the safest next vertical slice.
3. Compare parallel branches and recent changes before editing; preserve unrelated work and never silently replace another workstream.
4. Treat chat summaries, screenshots, stale plans, and remembered intent as leads until reconciled with current repository evidence and explicit user requirements.
5. Mark stale, contradictory, missing, or unverified project state rather than inventing continuity.
6. Produce a compact continuation packet usable from phone or another agent: outcome, current state, active branch/PR, evidence, blockers, next action, and rollback/handoff notes.
7. When repeated continuity failures occur, propose a repository-level regression, registry field, template, or skill improvement instead of relying on more prose.
8. Keep each product repository authoritative for its code and product-specific decisions.

Deliver a source-linked continuity packet and a prioritized next-step plan that can be resumed safely by another qualified agent.
