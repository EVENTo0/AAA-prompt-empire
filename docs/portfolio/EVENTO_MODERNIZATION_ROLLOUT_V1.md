# EVENTO Modernization Rollout v1

Goal: migrate existing and future EVENTO work onto Memory + Agent Contract + One-Click Control Plane without destabilizing active delivery.

## Governing priority
Finish > Start.
Reuse Before Rebuild.
Smallest Valuable Product.
Evidence Before Status.
Revenue Before Expansion.

## Capacity
Maximum:
- 3 Active
- 5 Supporting

## Current Active lane
1. EVENTO revenue acceptance / acquisition-to-customer handoff
2. Empire / Node24 / control-plane maintenance and modernization
3. Mobile readiness and device acceptance

## Supporting lane
1. OCTA founder security/control-plane
2. OCTA Voice
3. EVEX recovery
4. Portfolio registry
5. One reusable revenue-adjacent template

Everything else remains queued/future-lab unless promoted by the portfolio governor.

## Rollout sequence

### Phase A — Control plane first
- EVENTO Memory v1
- EVENTO Agent Contract v1
- task/evidence schemas
- capability registry
- one-click dashboard specification
- regression/eval gates

### Phase B — Pilot on 3 projects
Apply contracts to:
- Evento-project-development-v1
- Evento-One
- evento-mobile

Required result:
website -> EVENTO ONE -> mobile follows one source-linked execution/evidence contract.

### Phase C — Shared engineering projects
Adopt Memory/Agent Contract in:
- Evento-octa-v10
- AAA-prompt-empire
- Ev-Bot
- octa-xr-webar
- AEGIS

### Phase D — Venture rollout
Each venture receives:
- project manifest
- current objective
- task contract
- memory namespace
- agent routing
- quality gates
- preview/build lane
- rollback path

No venture gets full automation until its pilot gates pass.

## Platform lanes
Projects declare only applicable outputs:
- Vercel web preview
- Supabase data/backend
- Android APK/AAB
- iOS/Xcode/TestFlight-ready build
- Windows executable
- Unity scene/build/simulator
- Blender source/export/GLB
- print/content artifact

## Definition of modernization complete
A project is modernized when:
1. registered in canonical portfolio;
2. has Current Objective + Next Action;
3. has task/evidence contract;
4. can build a Context Pack;
5. routes through registered agents;
6. produces evidence-linked preview/build/test results;
7. captures reusable learning;
8. has explicit release/approval boundaries.

## Non-goal
Do not rewrite all projects or standardize every code stack. Standardize control, evidence, memory and handoff while preserving the best-fit implementation stack.
