# AAA+ Engineering Empire Documentation

This directory is the documentation source of truth.

## Domains

- `adr/` — architecture and operating decisions
- `verification/` — evidence and release confidence
- `architecture/` — system architecture, boundaries, interfaces, and data flows
- `ai/` — AI systems, prompts, tools, evaluations, safety, latency, and cost
- `game/` — gameplay, simulation, content, rendering, multiplayer, and platform pipelines
- `product/` — product vision, requirements, journeys, roadmaps, and acceptance criteria
- `security/` — threat models, controls, privacy, secrets, and incident response
- `deployment/` — environments, infrastructure, CI/CD, migrations, rollback, and runbooks
- `testing/` — test strategy, quality gates, fixtures, coverage, and regression policy

## Documentation rule

Documentation must describe the implemented system, not an aspirational system. Proposed designs must be explicitly marked `PROPOSED`; accepted decisions must be recorded in an ADR; implemented and verified behavior must link to evidence.
